## 1. Purpose

FAM's orchestration logic — pricing, budgets, confirmation, speculation — is framework-agnostic in design. But it must hook into a concrete agent framework to intercept tool calls, inject messages, read agent responses, and track token generation. The adapter layer bridges this gap.

An adapter implements a standard interface that the orchestrator core depends on. The adapter translates between FAM's internal operations (intercept a tool call, inject a pricing signal, record token counts) and the specific mechanics of the agent framework (LangGraph node insertion, OpenAI-style function call interception, etc.). This allows FAM's core modules to be developed and tested against the abstract interface while concrete adapters handle framework-specific wiring.

Per the architecture overview (spec 00), LangGraph is the primary and initially the only supported framework. The adapter architecture is defined here so that a second adapter can be added later without modifying any orchestration module, but the implementation priority is the LangGraph adapter. A secondary lightweight adapter targeting the generic OpenAI chat completions pattern is specified to demonstrate that the interface is not LangGraph-specific, but it is lower priority and may be deferred.

This spec defines the abstract adapter interface, the LangGraph concrete adapter (including node wrapping, state extension, and graph builder integration), and the secondary OpenAI-style adapter sketch.

## 3. Abstract Adapter Interface

The adapter interface is a Python `Protocol` class that defines every operation FAM's orchestration layer needs from an agent framework. All orchestration modules depend on this interface, never on a concrete adapter class.

```python
from typing import Protocol, AsyncIterator
from decimal import Decimal
from dataclasses import dataclass


@dataclass(frozen=True)
class InterceptedToolCall:
    """A tool call intercepted by the adapter before execution."""

    tool_call_id: str
    agent_id: str
    tool_name: str
    tool_args: dict
    raw_framework_object: object  # Framework-specific tool call object (opaque to FAM core)
    timestamp: float


@dataclass(frozen=True)
class AgentResponse:
    """An agent's parsed response to a FAM-injected message."""

    agent_id: str
    raw_text: str
    parsed_decision: str | None    # "approve", "defer", "cancel", or None if unparseable
    confidence: float              # 0.0–1.0, parser's confidence in the parsed decision
    tokens_in_response: int
    timestamp: float


@dataclass(frozen=True)
class TokenGenerationEvent:
    """Report of tokens generated by an agent in one generation step."""

    agent_id: str
    tokens_generated: int
    is_speculative: bool
    cumulative_tokens: int         # Total tokens for this agent in current task
    timestamp: float


class FrameworkAdapter(Protocol):
    """Abstract interface between FAM orchestration and an agent framework.

    Every concrete adapter must implement all methods. The orchestrator core
    calls these methods; the adapter translates to framework-specific operations.
    """

    # --- Agent Lifecycle ---

    async def register_agent(
        self,
        agent_id: str,
        agent_config: dict,
    ) -> None:
        """Register an agent with the adapter.

        The adapter performs framework-specific setup: extending state schema,
        wrapping tool nodes, registering callbacks, etc.

        agent_config contains framework-specific settings (e.g., graph reference
        for LangGraph, model name for OpenAI adapter).
        """
        ...

    async def deregister_agent(self, agent_id: str) -> None:
        """Remove an agent from the adapter.

        Cleans up framework-specific state, cancels pending operations,
        removes callbacks.
        """
        ...

    # --- Tool Call Interception ---

    async def intercept_tool_call(
        self,
        agent_id: str,
    ) -> InterceptedToolCall | None:
        """Wait for and return the next tool call from the given agent.

        Returns None if the agent completes without making a tool call.
        The adapter hooks into the framework's tool-calling mechanism
        to capture outgoing calls before execution.
        """
        ...

    async def deliver_tool_result(
        self,
        agent_id: str,
        tool_call_id: str,
        tool_name: str,
        result: str,
    ) -> None:
        """Deliver a tool result to the agent's conversation.

        Formats the result in the framework's expected tool-result format
        and injects it into the agent's state.
        """
        ...

    # --- Message Injection ---

    async def inject_system_message(
        self,
        agent_id: str,
        content: str,
        metadata: dict | None = None,
    ) -> str:
        """Inject a system message into the agent's conversation.

        Used for pricing signals, confirmation requests, budget warnings,
        speculative prompts, and other FAM-to-agent communication.

        Returns a message ID that can be used to reference or remove
        the message later.
        """
        ...

    async def inject_tool_call_rejection(
        self,
        agent_id: str,
        tool_call_id: str,
        tool_name: str,
        reason: str,
    ) -> None:
        """Inject a message indicating a tool call was rejected or cancelled.

        The agent sees this as a tool result indicating the call was not executed.
        """
        ...

    # --- Agent Response Reading ---

    async def read_agent_response(
        self,
        agent_id: str,
        timeout_seconds: float = 30.0,
    ) -> AgentResponse:
        """Wait for the agent to generate a response and return it.

        Used after injecting a confirmation request to read the agent's decision.
        The adapter must handle the case where the agent generates a multi-turn
        response (only the first response containing a decision is returned).
        """
        ...

    # --- Token Tracking ---

    def on_token_generation(
        self,
        callback: "Callable[[TokenGenerationEvent], Awaitable[None]]",
    ) -> None:
        """Register a callback invoked after each LLM generation step.

        The callback receives token count information for budget metering
        and speculative token tracking.
        """
        ...

    # --- State Access ---

    async def get_agent_state(self, agent_id: str) -> dict:
        """Return the current framework-specific state for the agent.

        Used by the speculative continuation manager for checkpointing.
        """
        ...

    async def set_agent_state(self, agent_id: str, state: dict) -> None:
        """Replace the agent's framework-specific state.

        Used by the speculative continuation manager for rollback.
        """
        ...

    # --- Execution Control ---

    async def suspend_agent(self, agent_id: str) -> None:
        """Suspend the agent's execution (pause LLM generation).

        Used during confirmation flow and speculative rollback.
        """
        ...

    async def resume_agent(self, agent_id: str) -> None:
        """Resume a suspended agent's execution."""
        ...

    async def is_agent_active(self, agent_id: str) -> bool:
        """Check whether the agent is currently executing."""
        ...
```

## 5. LangGraph Adapter

The LangGraph adapter is the primary and fully-featured adapter. It integrates FAM into LangGraph by wrapping user-defined `StateGraph` instances with FAM-managed nodes that intercept tool calls, inject pricing signals, and track token generation.

### 5.1 Architecture

The LangGraph adapter does not modify user-defined graphs. Instead, it wraps them. The user builds their agent graph as normal (LLM node → tool node → LLM node, etc.). The adapter's graph builder replaces the user's tool node with a FAM-managed tool node that performs interception, confirmation, and dispatch before calling the original tool function.

```
User's Original Graph:
    LLM Node ──▶ Tool Node ──▶ LLM Node
                     │
                (calls tool directly)

FAM-Wrapped Graph:
    LLM Node ──▶ FAM Tool Node ──▶ LLM Node
                     │
                     ├── 1. Intercept tool call
                     ├── 2. Check budget
                     ├── 3. Confirm (if needed)
                     ├── 4. Dispatch via queue
                     ├── 5. Inject result
                     └── (or defer → speculative)
```

### 5.2 FAMState Schema Extension

The adapter extends the user's LangGraph state with FAM-managed fields. These fields are defined as a `TypedDict` that is merged with the user's state schema at graph wrapping time.

```python
from typing import TypedDict, Annotated
from decimal import Decimal
from langgraph.graph import add_messages


class FAMState(TypedDict, total=False):
    """FAM-managed state fields injected into every wrapped graph.

    These fields are read and written exclusively by FAM nodes.
    User-defined nodes should not access them directly.
    """

    fam_agent_id: str
    fam_budget_balance: Decimal
    fam_current_reasoning_price: Decimal
    fam_current_tool_prices: dict[str, Decimal]
    fam_pricing_signal: str
    fam_pending_tool_calls: list[dict]
    fam_speculative_mode: bool
    fam_capability_tier: str
    fam_messages: Annotated[list, add_messages]
```

All FAM fields are prefixed with `fam_` to avoid collision with user-defined state fields. The `fam_messages` field uses LangGraph's `add_messages` reducer so that FAM-injected messages accumulate rather than overwrite.

### 5.3 FAM Tool Node

The FAM tool node is the central interception point. It replaces the user's tool-calling node in the wrapped graph.

```python
from langgraph.prebuilt import ToolNode


class FAMToolNode:
    """LangGraph node that intercepts tool calls for FAM processing.

    Replaces the user's ToolNode in the wrapped graph. Delegates actual
    tool execution to the original ToolNode after FAM processing.
    """

    def __init__(
        self,
        original_tool_node: ToolNode,
        orchestrator: "Orchestrator",
        adapter: "LangGraphAdapter",
    ) -> None:
        self._original = original_tool_node
        self._orchestrator = orchestrator
        self._adapter = adapter

    async def __call__(self, state: dict) -> dict:
        """Process a tool call through the FAM pipeline.

        1. Extract the pending tool call from LLM output in state.
        2. Look up current tool price and agent budget.
        3. Determine whether confirmation is needed.
        4. If auto-approved: deduct budget, dispatch, inject result.
        5. If confirmation needed: interrupt graph, inject confirmation
           request, await agent decision.
        6. If deferred: hand off to speculative continuation manager.
        7. If cancelled: inject cancellation notice.
        8. Return updated state.
        """
```

The node uses LangGraph's `interrupt()` function to pause graph execution when waiting for agent decisions during the confirmation flow. The interrupt mechanism yields control back to the event loop, allowing other agents to execute while this one waits.

### 5.4 Pricing Signal Injection Node

A separate node that runs before each LLM invocation to inject the latest pricing signal into the agent's context.

```python
class FAMPricingNode:
    """LangGraph node that injects pricing signals before LLM calls.

    Runs immediately before the LLM node. Reads the latest prices from
    the orchestrator, formats them at the agent's tier, and injects
    a system message into the conversation.
    """

    def __init__(
        self,
        orchestrator: "Orchestrator",
        formatter: "TieredSignalFormatter",
    ) -> None:
        self._orchestrator = orchestrator
        self._formatter = formatter

    async def __call__(self, state: dict) -> dict:
        """Inject pricing signal and return updated state."""
```

This node does not interrupt execution. It reads the latest `PriceUpdate`, formats a pricing signal at the agent's capability tier, and adds it to `fam_messages`. The pricing signal is injected as a system message so the LLM sees it in context before generating its next response.

### 5.5 Token Tracking Callback

The adapter registers a callback with LangGraph's streaming interface to count tokens as they are generated. For non-streaming execution (`ainvoke`), token counts are read from the LLM response metadata after each LLM node completes.

```python
class TokenTracker:
    """Tracks token generation per agent for budget metering."""

    def __init__(self, adapter: "LangGraphAdapter") -> None:
        self._adapter = adapter
        self._callbacks: list[Callable[[TokenGenerationEvent], Awaitable[None]]] = []
        self._cumulative: dict[str, int] = {}  # agent_id → total tokens

    async def on_llm_end(
        self,
        agent_id: str,
        response_metadata: dict,
    ) -> None:
        """Called after each LLM generation step.

        Extracts token count from response metadata and fires
        registered callbacks.
        """

    def register_callback(
        self,
        callback: Callable[[TokenGenerationEvent], Awaitable[None]],
    ) -> None:
        """Register a token generation callback."""
        self._callbacks.append(callback)
```

The token count source depends on the LLM provider. For OpenAI-compatible models, the adapter reads `response_metadata["token_usage"]["completion_tokens"]`. For other providers, the adapter falls back to an approximate count based on response text length divided by an estimated tokens-per-character ratio (configurable, default 0.25 for English).

### 5.6 Graph Builder

The graph builder is a utility that takes a user-defined `StateGraph` and wraps it with FAM nodes. This is the primary entry point for users integrating FAM with their LangGraph agents.

```python
from langgraph.graph import StateGraph


class FAMGraphBuilder:
    """Wraps a user-defined LangGraph StateGraph with FAM orchestration nodes.

    Usage:
        user_graph = StateGraph(MyState)
        # ... user defines nodes and edges ...

        builder = FAMGraphBuilder(orchestrator)
        wrapped_graph = builder.wrap(user_graph, agent_id="agent_1")
        app = wrapped_graph.compile(checkpointer=memory_saver)
    """

    def __init__(self, orchestrator: "Orchestrator") -> None:
        self._orchestrator = orchestrator

    def wrap(
        self,
        graph: StateGraph,
        agent_id: str,
        tool_node_name: str = "tools",
        llm_node_name: str = "agent",
    ) -> StateGraph:
        """Wrap the user graph with FAM nodes.

        Performs the following modifications:
        1. Extends the graph's state schema with FAMState fields.
        2. Replaces the tool node (identified by tool_node_name) with
           a FAMToolNode that wraps the original.
        3. Inserts a FAMPricingNode before the LLM node (identified
           by llm_node_name).
        4. Registers the agent with the adapter.

        Returns a new StateGraph with FAM integration. The original
        graph is not modified.
        """
```

The builder makes assumptions about the graph structure: there is a node named `"tools"` (or as configured) that handles tool execution, and a node named `"agent"` that runs the LLM. These are the default names used by LangGraph's prebuilt `create_react_agent()`. For custom graph topologies, the node names are configurable.

### 5.7 LangGraphAdapter Class

The concrete adapter class that implements `FrameworkAdapter`:

```python
class LangGraphAdapter:

    Implements the FrameworkAdapter protocol by translating FAM operations

    def __init__(self, config: AdapterConfig) -> None:

            name="langgraph",
            version="0.1.0",
            framework_name="LangGraph",
            framework_version_requirement=">=0.2.0",
            capabilities=frozenset({
                AdapterCapability.TOOL_INTERCEPTION,
                AdapterCapability.MESSAGE_INJECTION,
                AdapterCapability.TOKEN_TRACKING,
                AdapterCapability.STATE_CHECKPOINT,
                AdapterCapability.AGENT_SUSPENSION,
                AdapterCapability.STREAMING,

            max_concurrent_agents=None,
        )

    def set_orchestrator(self, orchestrator: "Orchestrator") -> None:
        """Bind the adapter to an orchestrator instance.

        Must be called before registering agents. Creates the graph builder.
        """
        self._graph_builder = FAMGraphBuilder(orchestrator)

    # --- FrameworkAdapter implementation ---

    async def register_agent(
        self,
        agent_id: str,
        agent_config: dict,
    ) -> None:
        """Register a LangGraph agent.

        agent_config must contain:
        - "graph": the compiled LangGraph Application or StateGraph to wrap
        - "thread_id": the LangGraph thread ID for this agent's execution
        - "capability_tier": (optional) override tier assignment

        The adapter wraps the graph and stores the registration.
        """

    async def deregister_agent(self, agent_id: str) -> None:
        """Remove agent registration and clean up pending interrupts."""

    async def intercept_tool_call(
        self, agent_id: str
    ) -> InterceptedToolCall | None:
        """Intercept via LangGraph's interrupt mechanism in the FAMToolNode."""

    async def deliver_tool_result(
        self, agent_id: str, tool_call_id: str, tool_name: str, result: str
    ) -> None:
        """Inject tool result as a ToolMessage into the LangGraph state."""

    async def inject_system_message(
        self, agent_id: str, content: str, metadata: dict | None = None
    ) -> str:
        """Inject as a SystemMessage with [FAM] prefix into graph state."""

    async def inject_tool_call_rejection(
        self, agent_id: str, tool_call_id: str, tool_name: str, reason: str
    ) -> None:
        """Inject as a ToolMessage with error content."""

    async def read_agent_response(
        self, agent_id: str, timeout_seconds: float = 30.0
    ) -> AgentResponse:
        """Resume graph after interrupt, capture LLM output, parse decision."""

    def on_token_generation(
        self, callback: "Callable[[TokenGenerationEvent], Awaitable[None]]"

        self._token_tracker.register_callback(callback)

    async def get_agent_state(self, agent_id: str) -> dict:

        """Write state to LangGraph's state store (for rollback)."""

    async def suspend_agent(self, agent_id: str) -> None:
        """Use LangGraph's interrupt to suspend execution."""

    async def resume_agent(self, agent_id: str) -> None:
        """Resume from interrupt by providing continuation input."""

    async def is_agent_active(self, agent_id: str) -> bool:
        """Check agent registration and execution status."""
```

## 6. LangGraph Interrupt Flow

The confirmation flow requires pausing agent execution, injecting a message, waiting for the agent to respond, and then routing based on the response. In LangGraph, this is achieved using the `interrupt()` mechanism.

### 6.1 Interrupt During Tool Interception

When the FAMToolNode determines that confirmation is needed:

1. The node calls `interrupt(confirmation_request)`, which raises a `GraphInterrupt` exception.
2. LangGraph catches this and saves the current state to the checkpointer.
3. The graph execution returns to the caller with an interrupt payload containing the confirmation request.
4. The adapter receives the interrupt payload and delivers it to the orchestrator's confirmation handler.
5. The confirmation handler formats the request and waits for resolution.
6. When the agent's decision is available (from re-invoking the graph with the decision as input), the adapter resumes the graph from the interrupted state.
7. The FAMToolNode reads the decision from the resumed state and proceeds accordingly.

```python
from langgraph.types import interrupt


async def _handle_confirmation(
    self,
    state: dict,
    tool_call: InterceptedToolCall,
    tool_price: Decimal,
    budget_balance: Decimal,
) -> str:
    """Interrupt graph for confirmation and return the agent's decision.

    Returns one of: "approve", "defer", "cancel".
    """
    confirmation_request = self._format_confirmation(
        tool_call, tool_price, budget_balance
    )
    decision = interrupt(confirmation_request)
    return decision
```

### 6.2 Interrupt Timeout

If the agent does not respond within the configured timeout (`confirmation_timeout_seconds`, default 30.0), the adapter applies the default policy from the confirmation handler configuration: either auto-approve or auto-cancel. The timeout is implemented via `asyncio.wait_for()` around the graph re-invocation.

## 7. OpenAI-Style Adapter

The secondary adapter targets the generic OpenAI chat completions pattern — any system that sends messages to an LLM endpoint and receives responses with optional tool calls. This adapter is simpler than the LangGraph adapter because it does not have graph execution infrastructure, checkpointing, or interrupts.

### 7.1 Scope and Limitations

The OpenAI-style adapter supports:
- Tool call interception (by wrapping the chat completions call).
- Message injection (by prepending system messages to the conversation).
- Token tracking (from response metadata `usage.completion_tokens`).
- Agent response reading (by parsing the next completion response).

The OpenAI-style adapter does **not** support:
- State checkpointing (no graph state to checkpoint).
- Agent suspension/resumption (no graph execution to interrupt).
- Speculative continuation with rollback (no checkpoint mechanism).

Without checkpointing, the speculative continuation manager operates in a degraded mode: it can still inject speculative prompts and track speculative tokens, but rollback discards the speculative messages from the conversation list in memory rather than restoring a checkpointed state. This is less robust (it depends on the adapter correctly tracking which messages are speculative) but functional for simpler use cases.

### 7.2 Integration Pattern

The OpenAI-style adapter wraps the `openai.ChatCompletion.create()` (or `acreate()`) call with a middleware function. The wrapper:

1. Before the call: injects pricing signal as a system message at the start of the messages list.
2. After the call: inspects the response for tool calls. If present, intercepts them and routes through FAM's confirmation flow before allowing execution.
3. Tracks token usage from the response's `usage` field.

```python
class OpenAIStyleAdapter:
    """Lightweight adapter for OpenAI-compatible chat completions APIs.

    Wraps the completions call with FAM interception. Does not require
    LangGraph or any specific agent framework — works with any code that
    sends messages to an OpenAI-compatible endpoint.
    """

    def __init__(self, config: AdapterConfig) -> None:
        self._config = config
        self._agents: dict[str, AgentRegistration] = {}
        self._conversations: dict[str, list[dict]] = {}  # agent_id → messages
        self._speculative_markers: dict[str, int] = {}    # agent_id → msg index
        self._token_callbacks: list[Callable] = []

    @property
    def info(self) -> AdapterInfo:
        return AdapterInfo(
            name="openai",
            version="0.1.0",
            framework_name="OpenAI Chat Completions",
            framework_version_requirement=">=1.0.0",
            capabilities=frozenset({
                AdapterCapability.TOOL_INTERCEPTION,
                AdapterCapability.MESSAGE_INJECTION,
                AdapterCapability.TOKEN_TRACKING,
            }),
            max_concurrent_agents=None,
        )

    def wrap_completion_call(
        self,
        agent_id: str,
        original_call: Callable,
    ) -> Callable:
        """Return a wrapped version of the chat completions call.

        The wrapped call intercepts tool calls and injects pricing signals.
        Drop-in replacement: same signature as the original call.
        """
```

### 7.3 Conversation Management

Without LangGraph's state management, the OpenAI adapter maintains its own conversation state per agent — a list of message dicts. FAM-injected messages (pricing signals, confirmation requests) are inserted into this list with metadata tags so they can be identified and removed later.

```python
@dataclass
class ManagedMessage:
    """A message in the adapter-managed conversation with FAM metadata."""

    role: str                # "system", "user", "assistant", "tool"
    content: str
    fam_injected: bool       # True if this message was injected by FAM
    fam_message_type: str | None  # "pricing_signal", "confirmation", "speculative", etc.
    message_id: str
    timestamp: float
```

## 8. Adapter Selection and Registration

The orchestrator selects the adapter at startup based on the `adapter` section of the global configuration (spec 12). Only one adapter is active per orchestrator instance.

```python
from fam.adapters.base import FrameworkAdapter
from fam.adapters.langgraph.adapter import LangGraphAdapter
from fam.adapters.openai.adapter import OpenAIStyleAdapter


ADAPTER_REGISTRY: dict[str, type[FrameworkAdapter]] = {
    "langgraph": LangGraphAdapter,
    "openai": OpenAIStyleAdapter,
}


def create_adapter(config: "OrchestratorConfig") -> FrameworkAdapter:
    """Instantiate the configured adapter.

    Reads config.adapter.name to select the adapter class from the registry.
    Passes config.adapter to the constructor.
    """
    adapter_name = config.adapter.name
    if adapter_name not in ADAPTER_REGISTRY:
        raise ValueError(
            f"Unknown adapter '{adapter_name}'. "
            f"Available: {list(ADAPTER_REGISTRY.keys())}"
        )
    adapter_cls = ADAPTER_REGISTRY[adapter_name]
    return adapter_cls(config.adapter)
```

Third-party adapters can be registered by adding to `ADAPTER_REGISTRY` before orchestrator startup. A future enhancement could support entry-point-based discovery, but explicit registration is sufficient for now.

## 9. Response Parsing

When the confirmation handler injects a confirmation request, the agent responds with free-form text. The adapter must parse this text to extract a structured decision. The response parser is shared across adapters.

### 9.1 Decision Extraction

```python
import re


class DecisionParser:
    """Parses agent free-form text responses to extract FAM decisions."""

    APPROVE_PATTERNS = [
        re.compile(r"\b(approve|confirm|proceed|yes|go ahead|execute|do it)\b", re.I),
    ]
    DEFER_PATTERNS = [
        re.compile(r"\b(defer|wait|postpone|later|speculate|continue reasoning)\b", re.I),
    ]
    CANCEL_PATTERNS = [
        re.compile(r"\b(cancel|abort|skip|don't|do not|no)\b", re.I),
    ]

    def parse(self, text: str) -> tuple[str | None, float]:
        """Parse agent text and return (decision, confidence).

        decision is one of "approve", "defer", "cancel", or None.
        confidence is 0.0–1.0 indicating parser certainty.

        The parser uses a priority-weighted keyword matching approach.
        If multiple patterns match, the one with the highest weight wins.
        If no patterns match, returns (None, 0.0).
        """
```

The parser is intentionally simple — keyword matching rather than LLM-based classification. This avoids the cost and latency of an additional LLM call and avoids recursive pricing issues (parsing consumes GPU, which affects prices). The evaluation harness (spec 14) should measure parsing accuracy across different models and tiers.

### 9.2 Structured Response Hints

To improve parsing reliability, the confirmation request prompt includes a structured response hint:

```
Respond with one of: APPROVE, DEFER, CANCEL
```

When the agent's response starts with one of these exact tokens, the parser has high confidence (1.0). When the agent provides a natural language response, the parser falls back to pattern matching with lower confidence. When confidence is below `min_parse_confidence` (default: 0.3), the adapter applies the default policy rather than acting on an uncertain parse.

## 10. Configuration

All adapter configuration is namespaced under `adapter` in the global FAM configuration (spec 12).

```yaml
adapter:
  # Which adapter to use: "langgraph" or "openai"
  name: "langgraph"

  # LangGraph-specific settings
  langgraph:
    # Default names of nodes in user graphs
    default_tool_node_name: "tools"
    default_llm_node_name: "agent"

    fallback_tokens_per_char: 0.25

    # Confirmation interrupt timeout
    confirmation_timeout_seconds: 30.0

    # Default confirmation timeout policy: "auto_approve" or "auto_cancel"
    confirmation_timeout_policy: "auto_cancel"

    # Whether to inject pricing signals before every LLM call
    inject_pricing_signals: true

    max_fam_messages: 50

  # OpenAI-specific settings
  openai:
    # Whether to inject pricing signals as system messages

    # Maximum system messages from FAM in conversation

    confirmation_max_retries: 3

  parsing:
    min_parse_confidence: 0.3
    default_decision_on_low_confidence: "auto_cancel"
    structured_hint_enabled: true
```

## 11. Error Handling

**Agent registration with invalid graph:** If the LangGraph adapter receives a graph that does not contain the expected tool or LLM nodes (by configured name), registration fails with a descriptive `ValueError`. The error message lists the available node names to help the user correct their configuration.

**Framework version mismatch:** On adapter initialization, the adapter checks the installed framework version against `framework_version_requirement`. If the requirement is not met, a `RuntimeError` is raised with the installed version and the required range.

**Tool call interception failure:** If the FAMToolNode encounters an unexpected state (e.g., the LLM output does not contain a tool call despite being routed to the tool node), it logs a warning and passes through to the original tool node unchanged. FAM does not block legitimate tool execution due to its own failures.

**Message injection failure:** If injecting a message into the conversation fails (e.g., state is locked, conversation list is corrupted), the error is logged and the FAM operation continues without the injection. The confirmation handler handles missing confirmations via its timeout policy.

**Token tracking failure:** If token count metadata is unavailable (model does not report usage), the adapter uses the fallback estimation and logs a warning. Inaccurate token counts degrade budget precision but do not break the system.

**Interrupt handling failure:** If a LangGraph interrupt is lost (e.g., the graph crashes during an interrupted state), the adapter detects this via the `_pending_interrupts` futures timing out. The timed-out interrupt resolves to the default policy.

**Concurrent access:** The adapter's agent registry (`_agents` dict) is modified only by `register_agent` and `deregister_agent`, which are called from the orchestrator's setup path (not concurrent with agent execution). Agent execution reads the registry but does not modify it. This avoids race conditions without explicit locking.

## 12. Metrics Emitted

The adapter layer emits the following metrics to the observability system (spec 13):

**Counters:** `adapter.agents.registered` (total registrations), `adapter.agents.deregistered`, `adapter.tool_calls.intercepted` (per agent_id, per tool_name), `adapter.tool_results.delivered`, `adapter.messages.injected` (per message_type: pricing_signal, confirmation, speculative, etc.), `adapter.responses.parsed` (per parsed_decision: approve, defer, cancel, unparseable), `adapter.parse.low_confidence` (responses below confidence threshold), `adapter.interrupts.created`, `adapter.interrupts.resumed`, `adapter.interrupts.timed_out`.

**Histograms:** `adapter.response.parse_time_ms` (time to parse agent response), `adapter.interrupt.duration_seconds` (time from interrupt creation to resumption), `adapter.token_tracking.generation_step_tokens` (tokens per generation step, for distribution analysis).

## 13. Testing Strategy

### 13.1 Unit Tests

**Decision parser:** Test with exact structured responses ("APPROVE", "DEFER", "CANCEL") — verify confidence 1.0. Test with natural language variants ("I'll approve this tool call", "let me defer for now", "no, cancel it"). Verify correct classification and reasonable confidence. Test with ambiguous responses ("maybe I should wait, but go ahead") — verify that the higher-priority match wins. Test with responses containing no decision keywords — verify None with confidence 0.0.

**FAMState schema:** Verify that merging FAMState with a user-defined TypedDict produces a valid combined schema. Verify that fam_ prefixed fields do not conflict with common user field names.

**Token tracker:** Provide mock response metadata with known token counts, verify correct event emission. Test fallback estimation with known text lengths. Verify cumulative tracking across multiple generation steps.

**Adapter info and capabilities:** Verify that each adapter reports correct capabilities. Verify that the adapter registry contains expected adapters. Verify that `create_adapter` raises for unknown adapter names.

### 13.2 Integration Tests

**Full LangGraph wrap-and-run:** Create a simple ReAct agent with LangGraph, wrap it with FAMGraphBuilder, run a task that triggers a tool call. Verify that the tool call is intercepted, a confirmation request is injected, and the tool result is delivered after approval.

**Confirmation flow with interrupt:** Run a wrapped graph, trigger a tool call that requires confirmation, verify that graph execution pauses at the interrupt. Resume with "approve", verify tool is dispatched. Run again with "cancel", verify tool is not dispatched and cancellation message is injected.

**Pricing signal injection:** Run a wrapped graph through multiple LLM turns. Verify that pricing signals are injected before each LLM call. Verify that signals reflect the latest prices from the orchestrator.

**Token tracking end-to-end:** Run a wrapped graph, verify that token generation events are emitted for each LLM response, verify cumulative counts are accurate, verify that speculative mode flag is correctly set.

**OpenAI adapter wrap-and-run:** Create a simple conversation loop using the OpenAI adapter's `wrap_completion_call()`. Verify that tool calls are intercepted and pricing signals are injected. Verify that token usage is tracked from response metadata.

### 13.3 Property-Based Tests

Use Hypothesis to generate random message lists and verify that FAM-injected messages (identified by `fam_injected=True`) can always be cleanly removed without affecting user messages. Generate random agent responses and verify that the decision parser always returns a valid tuple `(str | None, float)` with confidence in [0.0, 1.0]. Generate random `fam_` prefixed field names and verify they do not collide with a set of common LangGraph state field names.

## 14. Dependencies

**Internal:** `fam/types.py` (shared types), `fam/config/schema.py` (configuration), `fam/signals/formatter.py` (pricing signal formatting), `fam/signals/protocol.py` (message format), `fam/confirmation/handler.py` (confirmation flow), `fam/speculative/manager.py` (speculative state queries).

**Standard library:** `asyncio`, `dataclasses`, `re`, `time`, `logging`, `enum`, `uuid`, `typing`.

## 15. Open Questions

**Streaming token tracking.** The current design counts tokens after each complete LLM generation step (from response metadata). For streaming execution (`astream`), tokens arrive incrementally. Should the adapter count tokens per-chunk for real-time budget metering, or batch them per-response for simplicity? Per-chunk counting enables finer-grained budget control (the agent can be stopped mid-generation when budget is exhausted) but adds overhead and complexity. The initial implementation should use per-response counting; per-chunk counting can be added as an optimization.

**Multi-model agents.** A single LangGraph agent graph might invoke different LLM models at different nodes (e.g., a cheap model for planning and an expensive model for execution). The token tracker currently attributes all tokens to a single agent without distinguishing which model generated them. Per-model token tracking would improve budget accuracy when models have different inference costs. Deferred — the pricing engine currently sets a single reasoning price, not per-model prices.

**Graph topologies beyond ReAct.** The FAM graph builder assumes a simple LLM → tools → LLM loop. LangGraph supports arbitrary graph topologies including parallel branches, subgraphs, and conditional routing. The builder should handle at least linear and branching topologies. Arbitrary DAGs may require manual FAM node placement. The initial implementation targets the ReAct pattern; broader topology support is deferred.

**Hot-swapping adapters.** Can the adapter be changed at runtime without restarting the orchestrator? This would require deregistering all agents from the current adapter, switching the adapter instance, and re-registering agents with the new adapter. The complexity is high and the use case is rare. Deferred.

**Adapter-level rate limiting.** Should the adapter enforce its own rate limiting on LLM calls (separate from tool dispatch rate limiting)? This could prevent budget overruns when inference is very fast and budget deductions lag behind token generation. The budget manager's hard limit partially addresses this, but there is a window between token generation and budget deduction where the agent can overshoot. Deferred — measure the overshoot in practice first.
